# Inflated and adjusted response distributions

TorchGAMLSS represents boundary inflation as a distributional composition,
not as preprocessing. The point-mass probabilities can therefore have their
own formulas, smooths, offsets, or neural predictors.

## Generic point-mass composition

`PointMassFamily` adds one or more fixed response atoms to any compatible base
family. A single atom can use its probability directly:

```python
from torchgamlss import Beta, PointMassFamily

zero_adjusted_beta = PointMassFamily(
    Beta(),
    points=(0.0,),
    mass_parameter_names=("xi0",),
    parameterization="probability",
)
```

Here `xi0` lies in `(0, 1)`, has a logit link by default, and

```text
P(Y = 0) = xi0
f(y | 0 < y < 1) = (1 - xi0) f_BE(y).
```

For atoms at both zero and one, positive odds give an unconstrained
multinomial parameterization:

```python
zero_one_adjusted_beta = PointMassFamily(
    Beta(),
    points=(0.0, 1.0),
    mass_parameter_names=("xi0", "xi1"),
    parameterization="odds",
)
```

The default links for `xi0` and `xi1` are logarithmic. Their normalized
component probabilities are

```text
P(Y = 0)       = xi0 / (1 + xi0 + xi1)
P(0 < Y < 1)  =   1 / (1 + xi0 + xi1)
P(Y = 1)       = xi1 / (1 + xi0 + xi1).
```

These definitions match the one-boundary probability and two-boundary odds
conventions generated by `gamlss.inf::gen.Inf0to1()`.

## Named `gamlss.dist` families

| R family | TorchGAMLSS class or alias | Parameters |
| --- | --- | --- |
| `ZIP()` | `ZeroInflatedPoisson()` or `ZIP()` | `mu`, `sigma` |
| `ZINBI()` | `ZeroInflatedNegativeBinomial()` or `ZINBI()` | `mu`, `sigma`, `nu` |
| `BEZI()` | `BetaZeroInflated()` or `BEZI()` | `mu`, `sigma`, `nu` |
| `BEOI()` | `BetaOneInflated()` or `BEOI()` | `mu`, `sigma`, `nu` |
| `BEINF()` | `BetaInflated()` or `BEINF()` | `mu`, `sigma`, `nu`, `tau` |
| `BEINF0()` | `BetaInflatedZero()` or `BEINF0()` | `mu`, `sigma`, `nu` |
| `BEINF1()` | `BetaInflatedOne()` or `BEINF1()` | `mu`, `sigma`, `nu` |

`ZIP.sigma` and `ZINBI.nu` are direct zero-inflation probabilities. `BEZI.nu`
and `BEOI.nu` are direct boundary probabilities. `BEINF.nu` and `BEINF.tau`
are positive odds for masses at zero and one; the single-boundary `BEINF0` and
`BEINF1` variants also use positive odds.

`BEZI` and `BEOI` deliberately follow their R definitions, where `sigma` is
the positive total beta concentration:

```text
alpha = mu sigma
beta  = (1 - mu) sigma.
```

This differs from `Beta().sigma`, which lies in `(0, 1)` and satisfies
`Var(Y) = sigma² mu (1 - mu)`. `BEINF`, `BEINF0`, and `BEINF1` use the latter
`BE` parameterization for their continuous component.

## Fitting and diagnostics

Every mass parameter is an ordinary GAMLSS distribution parameter:

```python
from torchgamlss import GAMLSS, ZIP

model = GAMLSS.from_formula(
    ZIP(),
    {
        "mu": "count ~ x + offset(log_exposure)",
        "sigma": "~ treatment",
    },
    data,
)
fit = model.fit_rs_data(data)
```

The likelihood, parameter scores, and linked autograd path include both the
base component and the atoms. RS and CG use the working derivatives supplied
by the corresponding R families; joint L-BFGS and mini-batch optimization use
the exact differentiable likelihood.

Quantiles account for CDF jumps. Normal quantile residuals use
`P(Y < y) + U[P(Y <= y) - P(Y < y)]`, so randomization occurs at boundary
masses even when the base family is continuous. Supplying `uniforms=` makes
`quantile_residuals()`, `plot()`, `wp()`, and `bp()` reproducible.

Likelihoods, CDFs, scores, fitting, and residual probabilities remain on the
Torch device and support CUDA. Some inverse CDFs use the existing SciPy bridge
and return results to the original dtype and device.
